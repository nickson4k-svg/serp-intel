# VibeRadar — Журнал роботи та верифікацій (AI Work Log)

> Цей документ фіксує ключові етапи проєкту, виявлені розбіжності між початковими припущеннями та реальним API FreeSerp, виправлені помилки та результати ручної перевірки.

## 1. Хронологія ключових кроків

1. **Крок 0. Ініціалізація проєкту та правил**
   - Створено `CLAUDE.md` із жорсткими обмеженнями (лише ванільний JS/CSS/HTML, черга запитів &le; 3 req/s, кеш `sessionStorage`, заборона фейкових заглушок, обов'язкове зазначення джерела кожної цифри).
   - Створено `PLAN.md` з покроковою дорожньою картою.
   - Ініціалізовано Git-репозиторій, закріплено принцип «один крок — один коміт».

2. **Крок 1. Розвідка API (docs/api-notes.md)**
   - Досліджено `help=1` та специфікацію полів через прямі виклики API.
   - Зроблено запити `size=1` для білдерів:
     - `lovable`: 38 238 сайтів
     - `base44`: 15 534 сайти
     - `v0`: 4 245 сайтів
     - `bolt`: 695 сайтів
   - Виявлено реальний розподіл `dr_min=1` (від 8.9% у Lovable до 28.1% у Bolt).
   - Зафіксовано всі висновки у `docs/api-notes.md`.

3. **Крок 2. Шар даних (js/api.js + tests.html)**
   - Створено клієнт `js/api.js` із чергою `RequestQueue` (інтервал 350 мс між викликами).
   - Реалізовано кешування у `sessionStorage` з префіксом `viberadar_cache_v1:` та in-memory fallback.
   - Додано таймаут 10 с через `AbortController`.
   - Додано механізм повтору (до 2 спроб із backoff) при отриманні HTTP 502.
   - Додано обов'язкові параметри `agent=VibeRadar/1.0` та `project=VibeRadar`.
   - Експортовано методи `getStats()`, `countBy()`, `searchSites()`.
   - Створено діагностичну сторінку `tests.html` та перевірено всі методи на живому API.

4. **Крок 3. Сторінка «Pulse» (index.html, css/style.css, js/ui.js)**
   - Реалізовано дизайн-систему з автоматичною підтримкою світлої/темної теми через `prefers-color-scheme` та можливістю ручного перемикання.
   - Відображено картки нових сайтів (сьогодні, вчора, 7 днів, 30 днів), AI-стартапів та реальних сайтів.
   - Під кожною цифрою додано підпис із зазначенням конкретного поля (`stats.new.today`, тощо).
   - Побудовано чистий інтерактивний SVG-графік щоденної появи сайтів (`by_day`) із лінією середнього та тултіпами.
   - Додано таблиці топ-ніш (`top_ai_categories`) та стеків (`top_ai_source`).

5. **Крок 4. Сторінка «Builders» (builders.html)**
   - Створено порівняльні картки білдерів (Lovable, v0, Bolt, Base44).
   - Реалізовано асинхронне поступове заповнення: загальна кількість, частка сайтів із `dr_min=1`, топ-3 ніші.
   - Забезпечено ізольовану обробку помилок: збій запиту для одного білдера не блокує інші картки.
   - Додано модальне вікно для перегляду топ-5 сайтів за авторитетністю (`sort=dr`).

6. **Крок 5. Сторінка «Niche Map» (niche-map.html)**
   - Побудовано теплову матрицю 4 білдери &times; 15 ніш із `docs/api-notes.md`.
   - Кожна клітинка формується реальним викликом `countBy({ ai_source, ai_categories })`.
   - Додано живий індикатор прогресу завантаження, колірну шкалу інтенсивності та легенду.
   - Додано явний банер-застереження про те, що матриця показує валову кількість сайтів, а не їхню якість.
   - Клік на клітинку відкриває детальний перегляд 5 найсильніших сайтів за DR.

7. **Крок 6. Сторінки «Gap Finder», «Teardown» та «Method»**
   - `gap-finder.html`: фільтрація за нішами та максимальним DR, розрахунок індексу прогалин (Opportunity Score) та лістинг вразливих конкурентів.
   - `teardown.html`: вхідний аудит домену, розрахунок рейтингу за відкритим масивом із 7 правил SEO-гігієни із детальними поясненнями. Відсутній домен коректно маркується як «Не знайдено в індексі» (без помилки консолі).
   - `method.html`: документація методології, визначення термінів (`went_live`, `dr`, `ai_source`) та архітектури.

## 2. Реальні випадки розбіжностей та виправлень («Не вірити AI на слово»)

### Випадок 1: Припущення, що `ai_startups=1` охоплює всі сайти білдерів
- **Помилкове припущення**: Білдери (Lovable, v0, Bolt) створюють AI-стартапи, тому фільтр `ai_startups=1` поверне більшість їхніх сайтів.
- **Як виявили**: Під час запиту `ai_source=lovable&size=1` отримано `total: 38238`. Але при додаванні `ai_startups=1` результат склав лише **296**!
- **Причина**: Фільтр `ai_startups=1` у FreeSerp працює як жорсткий класифікатор саме *продуктових* AI-стартапів. Переважна більшість сайтів на білдерах — це лендинги персональних послуг, блоги, дорвеї або тестові сторінки без AI-функціоналу.
- **Що виправлено**: Для метрик активності білдерів на сторінках `builders.html` та `niche-map.html` використано прямий запит за `ai_source`, а різницю між загальною кількістю та `ai_startups=1` задокументовано у `api-notes.md` та `method.html`.

### Випадок 2: Значення поля `went_live` — не офіційна дата релізу стартапу
- **Помилкове припущення**: Трактувати `went_live` як дату заснування чи офіційного запуску бізнесу.
- **Як виявили**: Уважне вивчення документації `https://freeserp.ai/docs.php` показало застереження: *«went_live = the date FreeSerp first confirmed the site reachable, NOT the startup's official launch date»*.
- **Що виправлено**: У всіх картках, таблицях та підказках (Pulse, Builders, Teardown, Gap Finder) формулювання змінено на суворе: **«вперше зафіксовано живим»**.

### Випадок 3: Обробка відсутності домену в індексі Teardown
- **Помилкове припущення**: Якщо домен не знайдено, викидати помилку `throw new Error("Domain not found")` і показувати червоний алерт помилки.
- **Як виявили**: FreeSerp Main є індексом нещодавно виявлених та активних доменів (NRD pipeline). Багато старих або непроіндексованих зондом доменів у ньому відсутні. Це штатний стан індексу, а не збій сервера.
- **Що виправлено**: Відповідно до вимог ТЗ, стан відсутності домену в індексі показується як інформаційний блок **«Домен не знайдено в індексі FreeSerp Main»** із детальним поясненням причини, без червоної плашки збою.

### Випадок 4: Ризик блокування та помилок HTTP 502 через паралельні запити
- **Помилкове припущення**: Запустити всі 60 клітинок Niche Map через `Promise.all`.
- **Як виявили**: Під час агресивного паралельного надсилання запитів сервіс може повертати HTTP 502 (`search_phase_execution_exception`). FreeSerp є публічним відкритим API без ключів і просить дотримуватися ліміту &le; 3 запитів на секунду.
- **Що виправлено**: Реалізовано чергу `RequestQueue` із затримкою 350 мс між викликами, автоматичний бекофф-повтор при 502 та прогресивне заповнення таблиць із відображенням статусу для кожної клітинки окремо.
