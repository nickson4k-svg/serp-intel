# План сайту VibeRadar

## 1. Мета
Аналіз та візуалізація активності вебсайтів у ніші штучного інтелекту за даними відкритого індексу FreeSerp: відстеження щоденної динаміки запусків, часток платформ розробки, виявлення незайнятих ринкових ніш та швидкий аудит технічної гігієни окремих доменів.

## 2. Аудиторія
- Фаундери та розробники: пошук вільних сегментів ринку з низькою конкуренцією для запуску нових AI-продуктів.
- Маркетологи та SEO-фахівці: аналіз авторитетності доменів (DR), моніторинг активності ніш та діагностика базової технічної гігієни сайтів.
- Продуктові аналітики: дослідження проникнення платформ швидкої генерації коду (Lovable, v0, Bolt, Base44) у різні галузі.

## 3. Сторінки
1. **Pulse (`index.html`)** — щоденний пульс вебіндексу: кількість нових сайтів за 24г, 7 та 30 днів, векторний графік динаміки з підсвічуванням середнього рівня, рейтинги провідних категорій і стеків.
2. **Builders (`builders.html`)** — порівняння чотирьох ключових AI-платформ розробки (Lovable, v0, Bolt, Base44) за кількістю сайтів, часткою доменів із DR &ge; 1 та провідними нішами.
3. **Niche Map (`niche-map.html`)** — теплова матриця перетину 15 категорій та 4 платформ генерації коду з можливістю перегляду списку лідерів за DR для будь-якої клітинки.
4. **Gap Finder (`gap-finder.html`)** — пошук незайнятих ніш із фільтрацією за категоріями, платформами та рівнем конкуренції (DR), розрахунок оцінки можливостей (Opportunity Score).
5. **Teardown (`teardown.html`)** — компактна експрес-діагностика технічного стану та пошукової гігієни конкретного домену за 7 формалізованими критеріями.
6. **Method (`method.html`)** — опис методології збору даних, визначення поля went_live, пояснення шкали Domain Rating та технічних обмежень відкритого API.

## 4. Структура сайту
- **Навігаційна панель**: єдиний фіксований заголовок з логотипом, прямими посиланнями на всі розділи та перемикачем теми (світла/темна).
- **Інформаційний блок**: чіткий заголовок та підзаголовок без декоративного шуму.
- **Аналітичний блок**: інтерактивні графіки, матриці, табличні списки з числовим вирівнюванням та компактні форми пошуку.
- **Модальні вікна**: детальний перегляд топ-сайтів без перевантаження основної сторінки.
- **Шар даних (`js/api.js`)**: ізольований клієнт із чергою запитів, кешуванням у пам'яті вкладки та плавним переходом на резервні дані при збоях мережі.

## Етапи розробки та реалізації

### Етап 1. Розвідка API (docs/api-notes.md)
- Дослідження `help=1`, опису кінцевих точок та схеми параметрів.
- Тестування параметрів `ai_source` (`lovable`, `v0`, `bolt`, `base44`, `ai_likely`, `not_ai`, тощо).
- Тестування `ai_categories` з прапорцем `ai_startups=1` та без нього.
- Запити з `size=1` для збору реальних `total` та перевірки часу відповіді.
- Фіксація розбіжностей між очікуваннями та реальністю в `docs/api-notes.md`.

### Етап 2. Шар даних (js/api.js + tests.html)
- Створення клієнта API з чергою запитів (максимум 3 req/sec, затримка ~350ms).
- Кешування відповідей у `sessionStorage`.
- Таймаут 10 секунд на запит через `AbortController`.
- Автоматичний повтор до 2 разів при HTTP 502 з експоненційною затримкою.
- Обов'язкові query-параметри: `agent=VibeRadar/1.0`, `project=VibeRadar`.
- Експорт основних функцій:
  - `getStats()` — отримання зрізу індексу (`?stats=1`).
  - `countBy(filters)` — швидкий підрахунок кількості (`size=1`) за довільними фільтрами.
  - `searchSites(filters)` — повнотекстовий або параметричний пошук сайтів.
- Створення сторінки `tests.html` для верифікації кожної функції в реальному браузері.

### Етап 3. Сторінка «Pulse» (index.html, css/style.css, js/ui.js)
- Верстка з підтримкою тем (світла/темна) на основі `prefers-color-scheme` та ручним перемикачем.
- Метрики з `getStats()`:
  - Нові сайти: сьогодні (`new.today`), вчора, за 7 днів (`new.last_7d`), за 30 днів (`new.last_30d`).
  - AI-стартапи: загалом (`ai_startups.total`), сьогодні (`ai_startups.today`).
  - Джерело під кожною цифрою (наприклад, `stats.new.today`).
- Інтерактивний SVG-графік тренду за останні 30 днів (`by_day`).
- Рейтинг топ-ніш (`top_ai_categories`).
- Розподіл за Domain Rating (`dr.histogram`).

### Етап 4. Сторінка «Builders» (builders.html)
- Порівняльний аналіз білдерів: Lovable, v0, Bolt, Base44.
- Метрики для кожного:
  - Кількість створених сайтів (`total`).
  - Кількість та відсоток сайтів з Domain Rating >= 1 (`dr_min=1`).
  - Топ-3 домінуючі ніші для кожного білдера через `countBy`.
- Поступове (асинхронне) завантаження карток з індикаторами прогресу.
- Ізольована обробка помилок у кожній картці (одна помилка не ламає сторінку).

### Етап 5. Сторінка «Niche Map» (niche-map.html)
- Теплова матриця: білдери (`ai_source`) × ніші (`ai_categories`).
- Підрахунок `total` для кожної комбінації (`size=1`).
- Індикатор прогресу завантаження матриці.
- Колірна шкала інтенсивності з легендою.
- Дисклеймер: матриця показує кількість сайтів, а не їхню якість.
- Модальне вікно при кліку на клітинку: перегляд топ-5 найсильніших сайтів за DR (`sort=dr&order=desc`).

### Етап 6. «Gap Finder», «Teardown» та «Method»
- **Gap Finder (`gap-finder.html`)**:
  - Пошук ніш та підкатегорій з низькою конкуренцією (низький середній DR, мала частка AI-білдерів).
  - Фільтри за категорією, рівнем DR та мінімальною кількістю проєктів.
- **Teardown (`teardown.html`)**:
  - Аудит домену за пошуковим запитом (`q=domain&all=1&size=1`).
  - Масив формалізованих правил SEO-гігієни (статус 200, наявність та довжина title, наявність ai_summary, співвідношення тексту до html, прапорець real_site, сервер/CDN, Domain Rating).
  - Чітке розрізнення: «не знайдено в індексі» vs «помилка мережі».
- **Method (`method.html`)**:
  - Пояснення джерела даних FreeSerp, значення `went_live` («вперше зафіксовано живим»), методології розрахунків.

### Етап 7. Перевірка та аудит
- Перевірка джерел усіх числових значень у UI.
- Тестування обробки граничних випадків (пусті відповіді, 502, відсутність інтернет-з'єднання).
- Перевірка мобільної адаптивності (320px, 768px, 1200px+).

### Етап 8. Документування
- Підготовка `README.md` з інструкцією запуску.
- Ведення `docs/ai-log.md` з реальними викликами, виправленнями помилок та ручними перевірками.
