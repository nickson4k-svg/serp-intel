# VibeRadar — правила проєкту

## Контекст
Статичний сайт-аналітика на публічному API https://freeserp.ai/api.php (index=sites). Повний план — у PLAN.md. Тестове завдання: 2–4 години, потрібен робочий результат.

## Стек і межі
- Чистий HTML, CSS, JavaScript. Без фреймворків і без етапу збірки.
- Дозволені зовнішні скрипти лише з cdnjs, якщо справді потрібні (за замовчуванням — SVG вручну).
- Жодних ключів, акаунтів і бекенду. Деплой — GitHub Pages.

## Робота з API
- Усі виклики йдуть тільки через `js/api.js`. На сторінках прямого fetch немає.
- У кожному запиті додавати `agent=VibeRadar/1.0` і `project=VibeRadar`.
- Не більше 3 запитів на секунду: використовувати чергу з паузою (>= 334ms між викликами).
- Кеш у `sessionStorage`, таймаут 10 с, до 2 повторів при 502.
- Не вигадувати значення параметрів. Назви `ai_source` і `ai_categories` брати з `docs/api-notes.md`, а не з пам'яті.
- Завжди обробляти: порожній результат, помилку мережі, `total: 0`.

## Правила роботи
- Спочатку план кроку (3–5 рядків), потім код. Один крок — один коміт.
- Не переписувати файли цілком, якщо досить точкової правки.
- Усі числа в інтерфейсі мають мати джерело: запит, з якого вони отримані (дрібним текстом).
- Не називати `went_live` датою запуску. Писати «вперше зафіксовано живим».
- Після кожної сторінки перелічити, що перевірено, а що ні.

## Структура
- `index.html` — Pulse
- `builders.html` — Builders
- `niche-map.html` — Niche Map
- `gap-finder.html` — Gap Finder
- `teardown.html` — Teardown
- `method.html` — Method
- `css/style.css` — Стилі (тема світла/темна через prefers-color-scheme, адаптив)
- `js/api.js` — Шар даних
- `js/ui.js` — Спільні UI-хелпери (навігація, формати, бейджі)
- `docs/api-notes.md` — Нотатки розвідки API
- `docs/ai-log.md` — Журнал роботи та верифікацій
- `PLAN.md` — Загальний план реалізації
- `README.md` — Документація проєкту

## Заборонено
- Вигадувати дані, підставляти «заглушкові» цифри, показані як реальні.
- Додавати залежності без потреби.
- Прибирати обробку помилок заради спрощення коду.
